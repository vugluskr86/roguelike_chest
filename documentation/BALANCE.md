# Балансные кривые

`src/balance-config.ts` — типизированный источник чисел, которые меняют
сложность забега. Для обратной совместимости старый JavaScript получает те же
объекты через `CFG.HUNGER`, `CFG.DIFF`, `CFG.ROOMS`, `CFG.LADDER` и связанные
константы; новые системы должны импортировать `BALANCE` и функции кривых прямо.

## Голод и формы

| Группа | Параметры | Эффект |
| --- | --- | --- |
| `hunger` | `start`, `cap`, `perTurn` | Стартовый запас, предел и расход за обычный ход. |
| `hunger` | `passExtra`, `capture`, `vein`, `food` | Дополнительный расход паса и восстановление от источников еды. |
| `hunger.starveDegrade` | — | Частота деградации при нулевом голоде. |
| `forms.fatigueAfterCapture` | — | Cooldown формы после взятия. |
| `forms.enemyCaptureCooldown` | — | Пауза врага после взятия игрока. |
| `forms.degradationLadder` | тип → ранг | Порядок деградации форм. |

## Враги

Бюджет угрозы рассчитывается функцией `enemyThreatBudget(floor, width, height, share)`:

```text
(budgetBase + budgetGrow × (floor − 1)) × √(area / boardAreaReference) × share
```

`share` уменьшает бюджет каждой комнаты много-комнатного этажа. `enemyCountLimit`
задаёт отдельный потолок числа врагов. Стоимости, этажи открытия, лимиты элитных
врагов/ферзей, дальность, интервалы способностей и безопасная область спавна
находятся в `BALANCE.enemies`.

## Комнаты

`roomCountBounds(floor)` возвращает минимальное и максимальное число комнат;
рост задаётся `rooms.growEvery`, а верхняя граница — `rooms.cap`. Бюджет этажа
распределяется между комнатами по `rooms.budgetExp`.

## Правило изменения

Любое изменение числа в `BALANCE` требует:

1. Обновить этот документ с причиной и ожидаемым эффектом.
2. Запустить `npm run generation:report` и сравнить распределение с baseline.
3. Добавить/обновить тест кривой или симуляционный сценарий.
4. Не менять одновременно алгоритм генерации и балансные числа без отдельного
   измерения: иначе нельзя понять источник изменения сложности.

## Владелец и критерии приёмки

Владелец всех значений в `BALANCE` — геймдизайн. Техническое ограничение —
каждая кривая должна оставаться детерминированной и покрываться unit-тестом.
Перед изменением параметров фиксируются:

- отчёт `npm run generation:report` (уникальность, биомы, специальные клетки);
- число врагов и бюджет угрозы на этажах 1, 5, 10 и 18;
- эффект изменения на голод, награды и прохождение тестовых seed.

Изменение принимается только с указанной причиной, ожидаемым эффектом и
обновлённым baseline в описании PR.

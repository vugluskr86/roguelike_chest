# Контент-пайплайн «Эндшпиля» на ComfyUI

Блюпринты лежат в **API-формате** (`class_type` + именованные `inputs`). Это сделано
намеренно: имена входов не ломаются при обновлении кастом-нод, в отличие от порядка
виджетов в UI-формате. Загружаются так же — `Workflow → Open` (ComfyUI распознаёт
API-JSON и разворачивает граф), либо напрямую в очередь через `tools/queue.py`.

Плейсхолдеры `{{имя}}` подставляет `queue.py` из job-файлов. Руками в UI их надо
заменить на значения перед запуском.

---

## 0. Что генерить, а что нет

Честная рамка, чтобы не потратить неделю:

| Задача | Нейросеть | Итог |
|---|---|---|
| Карточный арт 512×768 (лор, боссы, экраны) | **отлично** | как ваши текущие 7 картинок, только лучше и повторяемо |
| Бесшовные текстуры пола/стен | **хорошо** | 90% работы, остатки шва добиваются в Aseprite за минуты |
| Пилоны, жернова, статичные препятствия | **хорошо** | нужна ручная вырезка альфы |
| scale9-рамки UI | **средне** | рамку даёт, но края и углы почти всегда доводятся руками |
| Спрайты фигур 48–96px, 8 направлений | **плохо в лоб** | см. §5 — без болванок консистентности не будет |

Общее правило: **генерим в 8–16 раз крупнее, ужимаем `nearest-exact`**. Прямая
генерация в 64px даёт кашу — модель не умеет в дискретную сетку, она рисует
«похоже на пиксель-арт», а не пиксель-арт. Ужимание + привязка к палитре
(`postprocess.py`) даёт настоящий чистый пиксель.

## 1. Что поставить

**Чекпоинт.** Для пиксель-арта берите SDXL-базу + pixel-art LoRA, либо
SD1.5 + pixel LoRA. SD1.5 быстрее и у него **несравнимо лучше экосистема
ControlNet** — для тайлов и персонажей это важнее качества базы. Flux/Klein для
пиксель-арта скорее мешает: слишком «фотографично» и плохо слушает
низкоуровневый контроль.

**ControlNet:**
- SD1.5 Tile — `control_v11f1e_sd15_tile.pth` (для workflow 03)
- SD1.5 depth / lineart / scribble — `control_v11f1p_sd15_depth`, `control_v11p_sd15_lineart` (для workflow 05)
- SDXL-аналоги — линейка xinsir / TTPlanet, если сидите на SDXL

**Upscale-модели:** `4x_foolhardy_Remacri.pth` (универсальный) или
`4x-UltraSharp`. Для пиксель-арта на финальном шаге апскейл почти не нужен —
он нужен только для крупного арта из §6.

### Заметки по вашим нодам

**Asymmetric Tiling** — живой форк `alsritter/asymmetric-tiling-comfyui`
(оригинал `tjm35` снят). Нода патчит `Conv2d` на circular padding по выбранным
осям, поэтому работает **только с UNet-моделями (SD1.5/SDXL)**, не с Flux.
Два подвоха:

1. `seed` объявлен как `("SEED",)` — тип из чужого пакета. Если при запуске
   ловите ошибку типа seed, поправьте одну строку в `custom_nodes/asymmetric-tiling-comfyui/node.py`:
   ```
   "seed": ("SEED", ),
   ```
   →
   ```
   "seed": ("INT", {"default": 0, "min": 0, "max": 0xffffffffffffffff}),
   ```
   и в `sample()`/`tile_ksampler()` заменить `seed['seed']` на `seed`.
   Блюпринты написаны под уже пропатченный (INT) вариант.
2. `tileX` / `tileY` принимают строки `"enable"` / `"disable"`, а не булевы.

**ControlNet Tile** — здесь он не для апскейла, а для **семейств тайлов**: один
утверждённый пол → шесть биомных вариаций с сохранённой структурой (workflow 03).

**Ultimate SD Upscale / TiledDiffusion** — только для крупного арта (§6). К
бесшовным тайлам их применять нельзя: они режут картинку на тайлы с
перекрытием и ломают циклическую непрерывность краёв.

**Klein Tiled Upscaler** — требует Flux2.Klein и связки
`GUIDER + SAMPLER + SIGMAS` (workflow 07). ⚠️ **Лицензия ноды —
Non-Commercial.** Вы готовите игру к релизу; если релиз платный, арт, прошедший
через эту ноду, — юридический риск. Держите её для черновиков, финал гоните
через workflow 06. Ещё её ограничение: длинные промпты вызывают дрейф стиля по
тайлам, автор тестировал только конфиг 4 шага / euler / 2x.

## 2. Быстрый старт

```bash
# один раз
pip install pillow numpy

# тайлы всех 6 биомов (сначала впишите чекпоинт в jobs/tiles.json)
python3 tools/queue.py jobs/tiles.json --out out/tiles

# проверка бесшовности + превью 3×3
python3 tools/tilecheck.py out/tiles/*.png --preview-dir out/preview

# пикселизация + привязка к палитре проекта
python3 tools/postprocess.py tile out/tiles/*.png --size 64 \
    --palette palette.json --outdir assets/tiles
```

`palette.json` — 24 цвета, снятые медианным срезом с ваших семи карточек
512×768. Привязка к ней — то, что физически склеивает генерённый арт с уже
нарисованным. Пересобрать: `postprocess.py palette screens/*.png --colors 24`.

## 3. Бесшовные тайлы

**Workflow 01** (`01_seamless_tile.json`) — txt2img 1024×1024 с asymmetric
tiling по обеим осям, затем `nearest-exact` до `tile_px`. Основной инструмент.

**Workflow 02** (`02_seam_fix_roll_inpaint.json`) — сдвигает картинку на пол-тайла
по обеим осям (края уезжают в центр), инпэйнтит крест по центру с
`denoise 0.45–0.65`, сдвигает обратно. Классический приём, и он работает с
**любой** картинкой — в том числе с уже сгенерённой на perchance. Построен
только на ядровых нодах, никаких зависимостей.

**Workflow 03** (`03_tile_variations_controlnet.json`) — от утверждённого тайла к
семейству. `denoise` 0.45 — та же плитка другого оттенка, 0.75 — другой
материал с тем же ритмом. Здесь ControlNet Tile и Asymmetric Tiling работают
вместе: первый держит структуру, второй — бесшовность.

Практика: `tile_px` берите кратным 8 и равным вашей клетке (или её половине).
На скриншоте клетка выглядит как 56–58px — если она не степень двойки, стоит
привести к 48 или 64, дальше будет проще с атласом и autotile.

Для **scale9-стен** (`autotile.js`) генерите не один тайл, а набор по 01, потом
собирайте маску соседей своим кодом — сеть не понимает blob47, и объяснять ей
это бессмысленно.

## 4. scale9 для UI

**Workflow 04** — и вот здесь Asymmetric Tiling раскрывается по-настоящему.
Он генерит четыре куска по отдельности:

| Кусок | Тайлинг | Зачем |
|---|---|---|
| `corner` | выключен обе оси | угол, зеркалится в остальные три |
| `edge_h` | **tileX only** | верх/низ, повторяется по горизонтали без шва |
| `edge_v` | **tileY only** | лево/право, повторяется по вертикали без шва |
| `fill` | обе оси | центр панели |

Это ровно то, ради чего асимметричный тайлинг придуман: край, бесшовный по
одной оси и с честными торцами по другой.

```bash
python3 tools/queue.py jobs/ui.json --out out/ui
python3 tools/slice9.py --name panel_bone \
    --corner out/panel_bone_corner.png --edge-h out/panel_bone_edge_h.png \
    --edge-v out/panel_bone_edge_v.png --fill out/panel_bone_fill.png \
    --outdir assets/ui
```

На выходе лист 3×3 и `panel_bone.json` с готовым `border-image` — вставляется в
CSS как есть, `image-rendering: pixelated` уже прописан. Учитывая вашу жалобу
на «диссонанс размеров модалок»: сделайте **один** `corner_px` (скажем, 32) на
все панели и **один** (16) на кнопки — тогда рамки будут визуально одной семьи
независимо от размера окна, и мобильная версия перестанет разъезжаться.

## 5. Персонажи и 8 направлений

Здесь надо принять три решения до генерации, иначе получите 88 красивых
несовместимых картинок.

**Решение 1. Половину направлений не генерить.** Шахматная фигура почти
симметрична относительно вертикальной оси. `west` = зеркало `east`,
`north-west` = зеркало `north-east`, `south-west` = зеркало `south-east`.
Остаётся **5 уникальных ракурсов** вместо 8. Флаг `--mirror-west` в
`make_char_jobs.py` это учитывает; зеркалить дешевле в рантайме
(`ctx.scale(-1,1)`) или на этапе атласа.

**Решение 2. Нужна болванка.** Без геометрического контроля модель на «facing
away» нарисует другого персонажа. Варианты по возрастанию качества:

- **Turnaround-лист.** Промптите один лист 4×2 «character turnaround sheet, 8
  angles, same character» в 1536×768, режете `tools/split_sheet.py`. Дёшево,
  консистентность средняя, годится для рядовых врагов.
- **Болванка из примитивов.** Слепите фигуру в Blender / Asset Forge из 4–5
  примитивов (конус + сфера + крест), отрендерите 8 ортокамер, сохраните
  depth-карты в `ComfyUI/input/endshpil_ref/<piece>_<dir>.png`. Полчаса на всех
  персонажей, потому что силуэты шахматных фигур — это буквально тела вращения.
  Это то, под что написан workflow 05.
- **IPAdapter / реference-only** поверх любого из двух — если поставите
  `ComfyUI_IPAdapter_plus`, подайте утверждённый `south` как reference с весом
  0.5–0.7. Даёт лучший результат по цветам и деталям.

**Решение 3. Фон — маджента.** В промпте `solid flat magenta background`,
дальше `postprocess.py sprite` вырезает по хромакею и делает альфу бинарной
(0 или 255 — полупрозрачных пикселей в пиксель-арте быть не должно, они
испортят тонирование в `sprites.js`).

```bash
python3 tools/make_char_jobs.py --group playable --mirror-west --out jobs/chars.json
python3 tools/queue.py jobs/chars.json --out out/chars
python3 tools/postprocess.py sprite out/chars/*.png --size 96 \
    --palette palette.json --outdir assets/sprites
python3 tools/atlas.py assets/sprites/*.png --cell 96 --out assets/atlas
```

`atlas.json` выходит в форме `{ "pawn": { "south": [x,y], ... } }` — под ваш
`sprites.js` с атласом.

Один seed на персонажа задаётся автоматически (`base + index*100`). Это главный
рычаг консистентности после ControlNet.

Отдельно: `batch: 4` в дефолтах — генерите по 4 варианта на направление и
выбирайте. На спрайтах брак идёт часто, а стоит он копейки.

## 6. Крупный арт 512×768

**Workflow 06** повторяет то, что вы уже получали на perchance, но управляемо:
генерация 832×1216 под TiledDiffusion (экономит VRAM), детализация Ultimate SD
Upscale ×2 с `denoise 0.28`, затем `nearest` вниз до ровно 512×768.

```bash
python3 tools/queue.py jobs/art.json --out out/art
```

`jobs/art.json` уже заполнен вашими сюжетными точками: четыре босса, Ров,
Жернова, Костоправ, Распайка, виньетка голода, концовка с троном.

Тёмная рамка ваших карточек — она в промпте (`dark chunky border frame`), но
надёжнее рисовать её кодом поверх, тогда она будет одинаковой на всех
картинках. Сейчас на семи референсах рамки заметно разные.

## 7. Порядок работ

1. **Палитра и размер клетки** — зафиксировать до генерации. Всё остальное
   висит на этих двух числах.
2. **Один пол одного биома** через 01, довести до идеала, утвердить.
3. Остальные 5 биомов — через 03 от утверждённого, `denoise` 0.6–0.75. Так они
   будут семьёй, а не шестью разными играми.
4. Стены и препятствия — 01 + ручная вырезка.
5. UI через 04, единые `corner_px`. Это ваш приоритет №1 по прошлому списку, и
   с готовым scale9 он закрывается быстрее, чем кажется.
6. Персонажи — последними, когда палитра и клетка уже не двигаются.
